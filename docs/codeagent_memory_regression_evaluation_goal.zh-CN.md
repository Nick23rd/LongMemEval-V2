# CodeAgent 内部记忆回归评测目标

## 1. 背景

本项目需要用于评估 CodeAgent 内部记忆机制的修改效果。典型修改包括：

- 记忆写入提示词；
- 记忆内容的组织与更新方式；
- 记忆召回提示词；
- 召回、排序、过滤和去重算法；
- 冲突信息与时间变化的处理策略。

评测的重点不是让 Agent 充当轨迹文件的读写器或检索器，再把单独输出的 `memory context` 交给外部 reader 回答。评测对象应当是 CodeAgent 从经历历史轨迹、形成内部记忆，到在全新会话中自动召回记忆并直接回答问题的完整能力。

## 2. 核心目标

每次修改 CodeAgent 的记忆机制后，使用相同数据和运行条件比较修改前版本与修改后版本，回答以下问题：

1. 修改后有多少原本答错的问题变为正确？
2. 修改后有多少原本答对的问题发生退化？
3. 总体准确率和各记忆能力分类的准确率是否提升？
4. 改进是否确实来自跨会话内部记忆，而不是模型先验、当前上下文、外部 reader 或原始轨迹泄漏？
5. 修改影响的是记忆写入、记忆召回，还是二者的组合？

主要比较对象是：

```text
candidate（修改后） - baseline（修改前）
```

`memory_off` 是辅助控制组，用来估计跨会话记忆相对于相同 Agent 经历但不持久化记忆时的实际贡献。

## 3. 三组实验

### 3.1 memory_off：关闭记忆控制组

CodeAgent 必须读取与其他组完全相同的历史轨迹，但关闭内部 auto-memory 功能。

```text
读取历史轨迹
→ 禁止形成持久记忆
→ 结束轨迹会话
→ 创建全新的问题会话
→ 保持记忆关闭且记忆目录为空
→ CodeAgent 直接回答问题
```

该组不是“不读取轨迹”的零上下文组。它用于控制轨迹理解过程、Agent 调用次数和模型推理成本，使组间主要差异集中在跨会话记忆机制上。

### 3.2 baseline：修改前记忆机制

```text
读取历史轨迹
→ 使用修改前机制形成持久记忆
→ 结束轨迹会话
→ 创建全新的问题会话
→ 挂载修改前形成的冻结记忆
→ CodeAgent 自动召回并直接回答问题
```

### 3.3 candidate：修改后记忆机制

```text
读取相同历史轨迹
→ 使用修改后机制形成持久记忆
→ 结束轨迹会话
→ 创建全新的问题会话
→ 挂载修改后形成的冻结记忆
→ CodeAgent 自动召回并直接回答问题
```

## 4. 必须保持一致的条件

除被评测的记忆机制及其开关外，三组实验必须保持以下条件一致：

- CodeAgent 主模型和模型参数；
- CodeAgent 的非记忆相关代码与版本；
- 历史轨迹集合及摄取顺序；
- 每条轨迹的输入内容；
- 最大轮数、超时和重试策略；
- 工具权限；
- 问题集合及执行顺序；
- 问题提示词和输出格式；
- 查询会话的隔离方式；
- 评分器和评分配置。

如果修改内容包含记忆写入提示词、存储格式或更新逻辑，`baseline` 和 `candidate` 必须分别从空状态重新构建记忆，不能共用已经形成的 memory state。

## 5. 会话和数据隔离

轨迹摄取与问题回答不得发生在同一会话中，否则关闭 auto-memory 的 Agent 仍可能通过当前上下文或会话历史获得答案。

每个问题必须在独立的新会话中执行，并满足：

- 不使用 `resume`、`continue` 或其他会话恢复能力；
- 不保留轨迹摄取会话的消息上下文；
- 问题工作目录不包含原始轨迹；
- 问题工作目录不包含人为生成的轨迹摘要或检索结果；
- 不向外部 reader 输出单独的 `memory context`；
- CodeAgent 的最终回答直接进入评分器；
- 查询不得修改用于该实验的冻结主记忆。

`memory_off` 还必须验证：

- auto-memory 确实处于关闭状态；
- 轨迹摄取后持久记忆目录为空；
- 查询时不存在来自轨迹会话的持久状态；
- 如果发现记忆文件或可恢复会话状态，本次运行应标记为隔离失败，而不是纳入正常评分。

## 6. 评分与对比

每道题对 `baseline` 和 `candidate` 做配对比较：

| 结果类型 | 定义 |
|---|---|
| `improved` | baseline 错误，candidate 正确 |
| `regressed` | baseline 正确，candidate 错误 |
| `both_correct` | 两个版本都正确 |
| `both_wrong` | 两个版本都错误 |

核心指标包括：

```text
准确率变化 = candidate_accuracy - baseline_accuracy

净改进题数 = improved - regressed

净改进率 = (improved - regressed) / 总题数

修改前记忆收益 = baseline_accuracy - memory_off_accuracy

修改后记忆收益 = candidate_accuracy - memory_off_accuracy
```

除总体结果外，还需要按以下记忆能力分类输出相同指标：

- static；
- dynamic；
- procedure；
- gotchas；
- abstention。

同时记录 UNKNOWN 率、错误率、查询延迟、构建延迟和 Token 用量。推荐对每个版本运行多次，并报告平均值、标准差及逐题多数票结果，以降低模型随机性造成的误判。

## 7. 写入与召回的归因实验

完整端到端比较为：

```text
A 写入 + A 召回  vs  B 写入 + B 召回
```

它用于判断整个候选版本是否优于基线版本。

当修改涉及召回算法时，还应增加冻结记忆上的隔离比较：

```text
同一份冻结记忆 + A 召回
vs
同一份冻结记忆 + B 召回
```

当修改涉及写入策略时，可以在相同召回实现下比较两份独立构建的记忆：

```text
A 写入形成的记忆 + 固定召回
vs
B 写入形成的记忆 + 固定召回
```

这些归因实验是诊断手段；最终版本判断仍以 CodeAgent 直接回答的端到端结果为主要依据。

## 8. 运行产物与可复现性

每次实验至少保存：

- 实验组名称：`memory_off`、`baseline` 或 `candidate`；
- CodeAgent 版本、提交号和可执行文件版本；
- 被评测记忆代码的版本或提交号；
- 写入提示词和召回提示词的内容哈希；
- 完整运行参数；
- 轨迹集合及顺序；
- 构建后的记忆文件哈希清单；
- 每题的原始最终回答、解析结果和得分；
- `improved`、`regressed`、`both_correct`、`both_wrong` 逐题列表；
- 总体、分类和多次运行的聚合指标；
- 会话隔离及主记忆未被查询修改的验证结果。

## 9. 验收标准

实现完成后应满足：

1. 三组都实际读取相同的历史轨迹；
2. `memory_off` 只关闭跨会话内部记忆，不省略轨迹摄取阶段；
3. `baseline` 与 `candidate` 能指定不同的记忆实现、提示词或版本；
4. CodeAgent 在新会话中直接回答，不经过固定外部 reader；
5. 问题阶段无法访问原始轨迹和摄取会话上下文；
6. 系统自动生成逐题配对 diff 和总体/分类回归指标；
7. 能区分端到端变化与写入、召回环节的局部变化；
8. 运行产物足以复现并审计一次版本比较。
